## 코어 프로필 vs 즉시 실행 모드 (Core-profile vs Immediate mode)

과거에 OpenGL을 사용한다는 것은 그래픽을 그리기 쉬운 방식인 **즉시 실행 모드(Immediate mode, 고정 기능 파이프라인이라고도 함)**로 개발함을 의미했습[...]

> **입문자 참고 - 즉시 실행 모드란?**: 즉시 실행 모드는 "삼각형을 그려라"라는 명령을 내리면 바로 화면에 삼각형이 그려지는 방식입니다. 직관적이지만 세부 제어가 어렵고, 현대 그래픽 카드의 병렬 처리 능력을 제대로 활용할 수 없습니다.

> **입문자 참고 - 코어 프로필이란?**: 코어 프로필은 "먼저 그릴 형태를 정의하고, 어떻게 그릴지 설정한 다음, 최종적으로 그려라"라는 단계별 방식입니다. 더 복잡하지만 그래픽 카드의 성능을 최대한 활용할 수 있고, 현대 그래픽 개발의 표준입니다.

> **입문자 참고**: 프로그래밍과 마찬가지로, 최신 버전이 항상 최고는 아닙니다. OpenGL 3.3은 출시된 지 오래됐지만, 대부분의 그래픽 카드에서 지원하며 기본 개념을 배우기에 충분합니다. 더 높은 버전은 최신 기술을 활용한 성능 최적화가 주이므로, 기초를 다진 후 배우는 것이 효율적입니다.

## 확장 (Extensions)

OpenGL의 훌륭한 특징 중 하나는 **확장(Extensions)** 지원입니다. 그래픽 회사에서 렌더링을 위한 새로운 기술이나 대규모 최적화 기법을 고안해 내면, 이[...]

> **입문자 참고**: 확장은 OpenGL이 모든 그래픽 카드에서 새로운 기능을 일괄 지원하기 전에, 특정 제조사의 카드에서만 먼저 사용할 수 있게 하는 메커니즘입니다. 예를 들어 NVIDIA가 새로운 렌더링 기법을 개발했다면, "GL_NV_xxxx"라는 이름의 확장으로 먼저 제공하고, 나중에 OpenGL 공식 명세에 포함될 때까지 기다립니다.

개발자는 이러한 확장을 사용하기 전에 사용할 수 있는지 여부를 질의해야 합니다(또는 OpenGL 확장 라이브러리 사용):

```cpp
if (GL_ARB_extension_name)
{ 
    // 하드웨어에서 지원하는 멋지고 현대적인 새로운 기능 수행
} 
else 
{ 
    // 확장이 지원되지 않음: 기존 방식으로 수행
}

```

> **입문자 참고**: 이 코드는 조건부 프로그래밍의 예입니다. 특정 기능을 사용 가능한지 먼저 확인한 후, 지원하면 최적화된 방식을 사용하고, 지원하지 않으면 대체 방식을 사용합니다. 이렇게 하면 다양한 하드웨어에서 프로그램이 호환되게 만들 수 있습니다.

OpenGL 버전 3.3에서는 대부분의 기술에 확장이 거의 필요하지 않지만, 필요한 경우 적절한 안내가 제공됩니다.

## 객체 (Objects)

OpenGL 라이브러리는 C 언어로 작성되었으며 다른 언어로의 많은 파생을 허용하지만, 그 핵심은 C 라이브러리로 남아 있습니다. C의 많은 언어 구조가 다[...]

> **입문자 참고**: OpenGL이 C로 작성되었다는 것은 OpenGL이 매우 하위 수준(low-level)이라는 뜻입니다. 따라서 객체 지향 개념(클래스, 상속 등)이 명시적으로 없고, 대신 함수와 ID를 통해 데이터를 관리합니다. 이는 복잡해 보이지만, 그래픽 카드와 직접 통신하기 위해서는 이 정도의 세밀한 제어가 필요합니다.

OpenGL에서의 객체는 OpenGL 상태의 일부분을 나타내는 옵션들의 집합입니다. 예를 들어, 그리기 창의 설정을 나타내는 객체가 있을 수 있습니다. 우리는 [...]

```cpp
struct object_name {
    float option1;
    int option2;
    char name[128];
};

```

> **입문자 참고**: 위 코드는 객체를 구조체로 생각하는 방식입니다. 객체는 여러 설정(옵션)을 하나의 그룹으로 묶은 것입니다. 예를 들어 "그릴 위치" 객체라면, x좌표, y좌표, z좌표를 하나의 객체로 관리합니다.

객체를 사용하고자 할 때의 일반적인 워크플로는 다음과 같습니다(OpenGL의 컨텍스트를 거대한 구조체로 시각화함):

```cpp
// OpenGL의 상태 (Context)
struct OpenGL_Context {
    ...
    object_name* object_Window_Target;
    ...    
};

// 객체 생성
unsigned int objectId = 0;
glGenObject(1, &objectId);

// 객체를 컨텍스트에 바인딩/할당
glBindObject(GL_WINDOW_TARGET, objectId);

// 현재 GL_WINDOW_TARGET에 바인딩된 객체의 옵션 설정
glSetObjectOption(GL_WINDOW_TARGET, GL_OPTION_WINDOW_WIDTH, 800);
glSetObjectOption(GL_WINDOW_TARGET, GL_OPTION_WINDOW_HEIGHT, 600);

// 컨텍스트 타겟을 다시 기본값으로 되돌림
glBindObject(GL_WINDOW_TARGET, 0);

```

> **입문자 참고 - 이 워크플로 이해하기**:
> 1. **생성**: `glGenObject()`로 새로운 객체를 생성합니다. 그러면 그 객체를 식별할 ID가 반환됩니다(예: 1, 2, 3...).
> 2. **바인딩**: `glBindObject()`로 생성한 객체를 현재 사용할 객체로 "선택"합니다. 이후의 모든 설정은 이 선택된 객체에 적용됩니다.
> 3. **설정**: `glSetObjectOption()`으로 선택된 객체의 옵션을 설정합니다. 마치 선택된 파일을 편집하듯이요.
> 4. **해제**: `glBindObject(..., 0)`으로 객체를 해제합니다. 0은 "아무 객체도 선택하지 않음"의 의미입니다.
> 
> 이는 마치 여러 개의 설정 프로필을 관리하는 것과 같습니다. 각 프로필(객체)마다 다른 설정을 저장해두고, 필요할 때마다 원하는 프로필을 활성화하는 방식입니다.

> **입문자 참고**: "비하드웨어" 부분은 GPU 메모리에 저장된다는 뜻입니다. 당신이 ID만 가지고 있고, 실제 데이터는 그래픽 카드의 메모리에 있는 것입니다. 이는 마치 은행 계좌번호만 가지고 있고, 실제 돈은 은행 서버에 저장된 것처럼 생각할 수 있습니다.
